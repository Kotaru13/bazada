
Документ — это основная единица хранения информации в MongoDB. Его можно сравнить со строкой в реляционной базе данных (например, SQL или PostgreSQL), но хранится он в формате BSON (бинарный JSON).

Документ обладает гибкой схемой: в одной коллекции могут находиться объекты с разным набором полей. При вставке не обязательно указывать все возможные поля. Каждый документ состоит из пар «ключ-значение» (по сути, словарь).

У любого документа всегда есть поле _id, которое уникально идентифицирует его внутри коллекции. Если это поле не задано явно, база данных сгенерирует его автоматически.

Коллекция — это группа документов (аналог таблицы в SQL). Её отличия:

Схема не требует предварительного описания.

Документы в коллекции логически однородны, но их структура может различаться.

Коллекция создаётся автоматически при первой вставке документа.

Поддерживаются индексы (составные, уникальные и другие).

Иерархия: «База данных → Коллекция → Документ → Поле»
BSON
Binary JSON — это бинарный формат сериализации данных, являющийся надмножеством JSON.

Производительность BSON значительно выше, так как длины строк и вложенных объектов хранятся в начале структуры. Это позволяет быстро пропускать поля при поиске, не разбирая весь документ целиком.

BSON добавляет новые типы данных:

ObjectID

Date

Binary (произвольные байты)

Decimal128

Regex

JavaScript

Структура документа BSON

cmd
  <размер (4 байта)> <элементы> <нулевой байт>
Формат каждого элемента

cmd
  <тип (1 байт)> <имя поля (cstring)> <значение>
Важно учитывать:

BSON часто занимает больше места из-за метаданных.

Одно и то же значение может быть представлено разными типами (например, int32 или double).

Некоторые замечания
Скалярное (обычное) поле — это поле, значением которого является простое значение: строка, число, boolean, дата, ObjectId и т.п.

Пример:

{
  "name": "ivane",
  "age": 30,
  "active": true
}
Вложенный документ — это поле, значением которого является другой документ (объект). Такой подход используется для моделирования связей «один-к-одному» и «один-ко-многим», когда данные логично хранить вместе.

Пример:


{
  "name": "ivane",
  "address": {
    "city": "tgt",
    "street": "fgfvb",
    "zip": "101000"
  }
}
Особенности:

Вложенность может быть любой глубины (до 100 уровней).

При поиске по вложенному объекту целиком важен порядок полей.

Массив — это поле, значением которого является упорядоченный список значений. Элементами могут быть скаляры, документы или другие массивы.

Пример:
{
  "name": "ivane",
  "hobbies": ["df", "gf", "ef"],
  "orders": [
    { "id": 1, "sum": 100 },
    { "id": 2, "sum": 250 }
  ]
}
